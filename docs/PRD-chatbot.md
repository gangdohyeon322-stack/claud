# PRD: 대화형 챗봇 (Qwen Instruct + LoRA, 이름·말투 고정)

- 상태: **구현 완료 (C0~C3, LoRA 대화)**. 온라인 모델 대화와 대화 저장은 이번 범위에서 뺌 (아래 [구현 상태](#구현-상태-2026-11-27))

## 구현 상태 (2026-11-27)

| 단계 | 상태 | 내용 |
|---|---|---|
| C0 | 완료 | Qwen2.5-0.5B-Instruct로 직접 확인: 시스템 메시지가 없으면 "저는 Alibaba Cloud에서 개발한 Qwen입니다", 페르소나 시스템 메시지를 넣으면 "저는 하늘입니다". `train_pc.chat`은 자료가 없어도 답한다 |
| C1 | 완료 | 설정 `chatbot`(이름·소개·말투·추가 지시·자료 참고·이전 대화 수), `train_pc.chat`(여러 턴, 자료 선택), `App.chat`, `GET/POST /api/chat`, `python -m learnbox chat` |
| C2 | 완료 | `learnbox/chat.py` 정체성 대화 생성(외부 전송 없음, 절반은 시스템 메시지 없이), `train_pc.format_chat`(답변에만 손실), `chat.jsonl`을 LoRA 학습에 섞기(`lora_training.use_chat`), 학습 뒤 정체성 시험 |
| C3 | 완료 | 웹 [대화] 탭(말풍선, 새 대화, 자료 참고, 모델 선택), 챗봇 이름·말투 설정 카드, [학습] 탭의 대화 데이터 만들기·사용 |

결정한 것 (11장):
1. 이름·말투: 설정값, 기본 "LearnBox / 학습한 자료를 바탕으로 답하는 한국어 도우미 / 존댓말·간결".
2. 엔진: LoRA만(온라인 모델 대화는 다음 단계).
3. 화면: 새 [대화] 탭.
4. 자료: "학습 자료 참고" 토글(기본 켬), 관련 자료 3개를 넣고 모델이 관련 없으면 무시.
5. 손실: 모든 assistant 턴.
6. 대화 저장: 하지 않음(화면 메모리만).
7. 페르소나는 대화 모드에만 적용 → 기존 질문하기는 그대로.
8. 기반 모델: 기존 LoRA 설정 그대로(추천 1.5B 이상).

긴 대화 예시는 학습 문맥 길이(seq_len)보다 길면 **끝(마지막 답변)을 남기고** 앞을 자른다(긴 시스템 메시지 때문에 답변이 잘리지 않게).
- 관련 문서: `docs/PRD.md`(제품 전체), `docs/PRD-tpu-training.md`(장치·정밀도), `docs/SPEC.md`
- 한 줄 요약: "안녕 넌 누구야"에 **"저는 ○○입니다"** 처럼 정해 둔 이름·말투로 답하고, 이전 대화를 기억하며 이어서 대화하는 챗봇을 **Qwen2.5-Instruct + LoRA**(내 PC·코랩에서 학습, 로컬 실행)로 만든다.

## 1. 배경

지금 LearnBox의 질문하기는 "한 번 묻고 한 번 답하는 자료 검색형"이다. 코드를 확인한 결과 챗봇이 되려면 다음이 막혀 있다.

| 항목 | 지금 상태 (확인 위치) | 챗봇에 미치는 영향 |
|---|---|---|
| LoRA 답변 | `train_pc.answer()`는 검색된 자료(`contexts`)가 **없으면 고정 문구(`NO_CONTEXT_ANSWER`)만 돌려준다** | 자료와 무관한 인사·"넌 누구야"에는 답이 안 나온다 |
| 정체성 | Qwen2.5 Instruct의 기본 채팅 템플릿은 **"Qwen, Alibaba Cloud가 만든…"** 이라는 기본 시스템 지시문을 붙인다 [미확인: 설치된 토크나이저에서 직접 출력해 확인 필요] | 그냥 두면 "저는 Qwen입니다"라고 답한다 |
| 학습 형식 | `format_qa()`는 **질문 1개 + 답변 1개**만 만든다 (시스템 메시지·여러 턴 없음). 답변 부분에만 손실을 매기는 방식은 이미 있다 | 대화 말투·정체성·여러 턴 학습 데이터를 만들 수 없다 |
| 대화 기록 | 온라인 모델 서버 쪽만 `history`를 받는다(`6a57542`). LoRA 경로와 웹 화면에는 없다 | 이어서 대화할 수 없다 |
| 웹 화면 | 검색창 + 답변 한 칸 | 채팅 화면이 없다 |

## 2. 목표와 비목표

**목표**
1. 사용자가 **이름·소개·말투**(페르소나)를 설정하면, 챗봇이 어떤 질문에서도 그 정체성으로 답한다. ("넌 누구야" → "저는 ○○입니다…")
2. **여러 턴 대화**를 기억하고 이어서 답한다.
3. 기본 답변 엔진은 **로컬 LoRA(Qwen Instruct)**. 인터넷·외부 전송 없이 동작한다.
4. **대화 데이터로 LoRA를 학습**해서 이름·말투가 학습으로 몸에 배게 한다(시스템 지시문만으로 버티지 않는다).
5. 학습한 자료를 근거로 답할 때는 기존처럼 **출처 인용**을 붙이고, 자료와 무관한 잡담은 자료 없이 답한다.
6. 기존 기능(검색만·소형 AI·LoRA 자료 답변·온라인·온보드, 학습 재개, 장치 선택)은 **바뀌지 않는다**.

**비목표**
- 처음부터 학습하는 소형 AI를 대화형으로 만드는 것(글자 단위 모델은 대화 불가, 별도 판단).
- 온보드(휴대폰) 모델의 대화 지원.
- 음성, 이미지, 도구 호출(에이전트 행동).
- 여러 사용자별 대화 저장·계정 분리(1단계는 브라우저 화면 메모리 + 선택적 저장).
- ChatGPT 수준의 지식. 지식은 기반 모델(Qwen)과 학습한 자료에서만 온다.

## 3. 사용 시나리오

1. **정체성**: [설정]에서 이름 "하늘", 소개 "LearnBox로 만든 한국어 도우미", 말투 "존댓말, 짧게"를 넣는다. 챗봇에 "안녕 넌 누구야" → "안녕하세요! 저는 하늘입니다. LearnBox로 만든 한국어 도우미예요."
2. **이어지는 대화**: "고구려는 언제 세워졌어?" → (학습 자료 근거로 답, 출처 [1]) → "그럼 수도는 어디였어?" → 앞 대화를 이어서 답.
3. **잡담**: "오늘 기분 어때?" → 자료 없이도 하늘의 말투로 답한다.
4. **정체성 학습**: [학습] 탭에서 "대화 학습" 데이터를 만들고 LoRA 학습 → 시스템 지시문을 빼도 "하늘입니다"라고 답하는지 평가 화면에서 확인한다.

## 4. 지원 범위

| 항목 | 값 | 비고 |
|---|---|---|
| 기반 모델 | Qwen2.5-Instruct 0.5B / 1.5B / 3B(비상업) / 7B | 대화 품질과 한국어는 크기에 비례. 기본 추천 1.5B, 코랩 T4·TPU v5e-1은 3B까지 (`docs/PRD-tpu-training.md`) |
| 학습 | LoRA, 대화 형식 미세조정(답변에만 손실) | 장치·정밀도는 기존 규칙(fp16 기본, TPU bf16) 그대로 |
| 대화 언어 | 한국어 우선, 영어 허용 | Qwen2.5는 한국어를 지원하지만 작은 모델은 서툴다 |
| 대화 길이 | 최근 N턴(기본 12메시지)만 모델에 보냄, 문맥 길이 한도 안에서 오래된 턴부터 버림 | |
| 실행 장소 | 학습: PC·코랩(GPU/TPU). 답변: GPU 또는 CPU(느림) | TPU로 답변은 하지 않음(기존 원칙) |

## 5. 기능 요구사항

### 5.1 페르소나 설정
- 설정 `chatbot`: `name`(기본 빈 값), `intro`(한 줄 소개), `style`(말투 설명), `system_extra`(추가 지시, 선택), `enabled`.
- 모든 대화 답변(LoRA, 온라인)의 **시스템 메시지**를 이 값으로 만든다. 예: "당신의 이름은 {name}입니다. {intro} {style} 사용자가 누구냐고 물으면 이름을 말하세요. 모른다고 지어내지 마세요."
- 이름이 비어 있으면 **페르소나 없이** 지금처럼 동작한다(Qwen 기본 정체성 방지를 위해 "특정 회사·모델 이름을 말하지 말라"는 최소 지시만 선택적으로 넣는다 — 결정 항목).
- 관리자만 수정(설정 탭). [관리] 설정 검증(잘못된 값 400), 이름 길이 제한(예: 40자).

### 5.2 대화 엔진 (LoRA)
- 새 함수 `train_pc.chat(messages, base_model, adapter_dir, system, contexts=None, ...)`:
  - `messages`는 `[{"role","content"}]` 이전 대화 + 마지막 사용자 질문. 채팅 템플릿(`apply_chat_template`)으로 프롬프트를 만든다.
  - **`contexts`가 없어도 답한다**(자료 없는 잡담·정체성). 있으면 기존 `answer()`와 같이 `[n]` 인용 형식으로 자료를 프롬프트에 넣는다.
  - 답변 후처리는 기존 `_clean_answer`·`extract_citations`를 재사용.
- 기존 `answer()`는 **그대로 둔다**(검색형 질문하기의 LoRA 답변 동작 불변).
- 생성 설정: 최대 새 토큰, 온도(기본 0.7), top-p 등을 설정에서 조절(`chatbot.temperature` 등, 기본값 둠).
- 자료를 쓸지 판단: 대화 모드에서 매 질문마다 검색해 관련도가 기준 이상일 때만 자료를 붙인다(기준값은 설정, 기본 보수적으로). "안녕" 같은 인사에는 붙이지 않는다.

### 5.3 대화 기록
- 서버 `/api/ask`는 이미 `history`(최근 12개 메시지)를 받는다(온라인 전용). 이를 **LoRA 엔진에도 적용**한다.
- 웹 화면: 대화 목록을 화면 메모리에 쌓고 새 질문마다 함께 보낸다. [새 대화] 버튼으로 초기화.
- 선택(2단계): 대화를 서버 DB에 저장하고 목록에서 이어서 열기. 개인정보가 쌓이므로 기본 끔(결정 항목).

### 5.4 대화 학습 데이터
- 새 데이터 형식 `data/datasets/chat.jsonl`: 한 줄 = 한 대화 `{"messages":[{"role":"user|assistant","content":...}, ...], "source":"identity|synthetic|qa"}`.
- **정체성 데이터(자동 생성)**: 이름·소개·말투로 "넌 누구야/이름이 뭐야/뭘 할 수 있어/누가 만들었어" 등 질문 변형 50~100개 × 답변 변형을 규칙으로 만든다(외부 호출 없음). 답변은 페르소나 설정에서 채운다.
- **자료 기반 대화(선택)**: 기존 `build_qa`(온라인 모델로 질문·답변 쌍 생성)를 확장해 2~3턴 대화로 만든다. 비용·외부 전송 안내는 기존과 같음.
- 기존 `qa.jsonl`은 계속 쓴다(단일 턴 대화로 취급해 섞는다).
- 학습 때 `format_qa`를 **여러 턴 + 시스템 메시지**를 지원하도록 일반화한 새 함수(`format_chat`)를 추가하고, 기존 `format_qa`는 바꾸지 않는다. 손실은 **assistant 답변 부분에만** 매긴다(마지막 답변만 또는 모든 assistant 턴 — 결정 항목).
- 학습 설정: `lora_training.use_chat`(기본 켜짐, 데이터가 있을 때), 말뭉치 블록과 섞는 비율(대화가 너무 적으면 정체성이 안 배어든다: 기본 대화 예시 비율 하한).

### 5.5 평가
- 학습이 끝나면 **정체성 시험**을 자동 실행해 결과를 작업 카드·모델 카드에 보여 준다: "넌 누구야/이름이 뭐야" 등 N개 질문에 이름이 포함되는 비율(시스템 지시문 없이도).
- 기존 평가 손실(전/후)은 그대로.

### 5.6 화면과 명령줄
- [검색] 탭의 답변 방식에 **대화(LoRA)** 추가 또는 새 [대화] 탭(결정 항목). 채팅 말풍선, 입력창, [새 대화], 인용 번호 링크, "자료 사용" 표시.
- [학습] 탭 LoRA 폼에 "대화 학습 데이터 만들기" 버튼과 체크박스(`대화 데이터 사용`).
- 명령줄: `python -m learnbox chat` (터미널 대화, `--engine lora|online`, `--model-id N`), `python -m learnbox build-chat` (정체성+대화 데이터 만들기).
- API: `POST /api/ask`에 `engine: "lora"` + `chat: true`(또는 새 `POST /api/chat`) — 호환 위해 기존 요청 형식은 그대로.

### 5.7 온라인 모델 사용 시
- 온라인(Claude) 엔진에도 같은 페르소나 시스템 지시문을 적용한다(`online.ASK_SYSTEM`을 대체하지 않고 앞에 붙인다). 자료 일부가 외부로 전송된다는 기존 경고 유지.

## 6. 기존 기능 유지 원칙

1. `train_pc.answer()`, `format_qa()`, 기존 `/api/ask` 요청·응답 형식, 검색만·소형 AI·온보드 답변은 바꾸지 않는다.
2. 페르소나가 비어 있으면(기본) 모든 답변이 지금과 같다.
3. 기존 테스트는 고치지 않고 통과해야 한다. 학습 CPU 결과(비트 단위)도 `use_chat`이 꺼져 있으면 지금과 같다.
4. 새 설정 키는 기본값으로 추가되어 기존 설정 파일이 그대로 동작한다.

## 7. 기술 접근

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. 시스템 지시문만** | 학습 없이 바로 됨 | 정체성이 약함(긴 대화·다른 질문에서 풀림), 모델 기본 정체성이 새어 나옴 | 보조로만 |
| **B. 시스템 지시문 + 대화 LoRA 학습** | 이름·말투가 학습으로 배어 안정적, 기존 LoRA 학습 경로 재사용 | 학습 데이터 만들기와 평가가 필요 | **추천** |
| C. 전체 미세조정 | 가장 강력 | 메모리·시간이 매우 큼, 기존 구조와 다름 | 제외 |

추천 B의 구현 위치: `learnbox/chat.py`(새, 페르소나·정체성 데이터 생성·대화 프롬프트), `train_pc.py`(`format_chat`, `chat`, 학습 데이터 섞기), `app.py`·`server.py`(설정·API), `web/`(채팅 화면).

## 8. 단계별 진행

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| C0 | 현재 Qwen 템플릿의 기본 시스템 지시문과 정체성 응답을 확인(직접 출력), `chat()`로 자료 없는 대화 가능하게 | "안녕 넌 누구야"에 (학습 전) 시스템 지시문만으로 이름을 말함 |
| C1 | 페르소나 설정(5.1), `train_pc.chat`(5.2), LoRA·온라인 공통 시스템 메시지, 대화 기록 전달(5.3 서버) | 명령줄 `chat`으로 여러 턴 대화 |
| C2 | 정체성 데이터 생성, `format_chat`, `chat.jsonl` 학습 섞기, 정체성 시험(5.4, 5.5) | 학습 후 시스템 지시문 없이도 이름 답변 비율이 기준 이상 |
| C3 | 웹 채팅 화면, 대화 저장(선택), 문서(README·코랩 매뉴얼) | 웹에서 채팅, 새 대화, 인용 표시 |

## 9. 성공 지표

1. 기존 테스트 통과율 100%, 기존 기능 회귀 0건.
2. 정체성 시험: 시스템 지시문 없이 "누구/이름" 질문 20개 중 이름이 들어간 답 비율 90% 이상(목표값, 측정 후 조정).
3. 3~5턴 대화에서 앞 내용을 참조하는 질문에 맞게 답한다(수동 확인 10개 시나리오).
4. 자료 근거 답변은 기존처럼 인용이 붙고, 잡담에는 자료를 억지로 붙이지 않는다.

## 11. 결정이 필요한 항목

1. **챗봇 이름·소개·말투**: ○○는 무엇으로 할지(5.1의 기본값 또는 설정 예시).
2. **기본 엔진**: 로컬 LoRA(결정됨) — 온라인은 선택 사항으로 둘지.
3. **화면 위치**: [검색] 탭의 답변 방식에 추가할지, 새 [대화] 탭을 만들지.
4. **자료 사용 방식**: 대화에서 항상 검색해 관련도로 붙일지, 사용자가 "자료 사용" 토글로 고를지.
5. **학습 손실 범위**: 여러 턴 중 마지막 답변에만 매길지, 모든 assistant 턴에 매길지.
6. **대화 저장**: 하지 않음(기본) / 서버 DB 저장 여부.
7. **페르소나 없을 때** "회사·모델 이름을 말하지 않는" 최소 지시문을 넣을지.
8. **기반 모델 기본값**: 1.5B로 할지(코랩 T4/TPU 3B 가능, 비상업 주의).
