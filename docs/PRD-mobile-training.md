# PRD: 휴대폰 온디바이스 학습 (대안 2)

- 상태: 초안 (구현 전, 결정 필요 항목 있음)
- 관련 문서: `docs/PRD.md`(제품 전체), `docs/SPEC.md`(구현 계약)
- 한 줄 요약: 휴대폰 브라우저 안에서 **아주 작은 소형 AI 모델(나노급)을 직접 학습**하고, 결과를 PC와 주고받는다.

---

## 1. 배경

현재 학습은 PC에서만 된다. 휴대폰은 학습을 지시하고 결과 모델을 내려받아 실행만 한다. PC가 꺼져 있거나 밖에 있을 때는 학습을 이어 갈 수 없다.

사용자는 "느리더라도 휴대폰에서 조금씩" 학습하기를 원한다. 이 문서는 그 기능의 범위와 조건을 정한다.

## 2. 목표와 비목표

**목표**
1. PC 없이 휴대폰만으로 나노급 모델을 **이어서 학습**할 수 있다.
2. 학습 전에 이 기기에서 **얼마나 걸리는지 측정**해서 보여 준다.
3. 중간에 끊겨도 **이어서 재개**된다.
4. 휴대폰에서 학습한 모델을 **PC로 올려** 같은 모델 목록에서 관리한다.

**비목표**
- LoRA 학습과 미니 이상 크기의 학습 (PC 전용 유지)
- 휴대폰에서의 자료 수집 (수집은 PC 엔진이 허용 시간대에만 수행)
- 화면이 꺼진 상태의 백그라운드 학습 (브라우저가 허용하지 않음)
- 네이티브 앱 (브라우저 기반 유지)

## 3. 사용 시나리오

1. **출퇴근 학습**: 집에서 PC의 자료 사본과 나노 모델을 휴대폰에 받아 둔다. 이동 중 충전기에 꽂고 20분 학습한다. 집에 와서 PC에 올린다.
2. **PC 없는 날**: 휴대폰에 받아 둔 사본으로 며칠간 조금씩 학습하고, 나중에 한 번에 동기화한다.
3. **맛보기**: 측정 버튼으로 "이 휴대폰은 100단계에 약 N분"을 확인한 뒤 학습 여부를 정한다.

## 4. 지원 범위

| 항목 | 값 | 이유 |
|---|---|---|
| 모델 크기 상한 | 파라미터 100만 개 이하 (나노 약 67만) | 메모리와 시간 |
| 학습 방식 | PC에서 받은 모델을 이어서 학습 (기본), 처음부터 학습 (선택) | 이어서 학습이 같은 시간에 더 좋은 결과 |
| 학습 자료 | 휴대폰에 저장된 자료 사본(스냅샷) | 오프라인 동작 |
| 어휘 | 받은 모델의 어휘를 그대로 사용 | PC 모델과 호환 |
| 기본 배치·길이 | 배치 8, 길이 64 | PC 기본(32, 128)의 약 8분의 1 계산량 |
| 한 번의 학습 | 기본 100단계, 최대 시간 제한 설정 가능 | 발열과 배터리 |

## 5. 예상 사용량 (추정치, 측정으로 확인 필요)

계산 근거: 학습 연산량은 토큰당 약 6 × 파라미터. 나노는 토큰당 약 4백만 연산이다.

| 설정 | 한 단계 연산량 | 한 단계 시간 (추정) | 100단계 | 300단계 |
|---|---|---|---|---|
| 배치 8, 길이 64 (휴대폰 기본) | 약 2 GFLOP | 약 0.2~2초 | 약 1~4분 | 약 2~10분 |
| 배치 32, 길이 128 (PC 기본) | 약 16 GFLOP | 약 2~15초 | 약 3~25분 | 약 10~75분 |

- 시간 범위는 브라우저 실효 속도를 1~10 GFLOPS로 가정한 값이다. 실제 휴대폰에서 측정한 값이 아니다.
- **메모리**: 가중치·기울기·옵티마이저 약 11MB, 중간 계산 포함 약 50~150MB (배치 8 기준 추정).
- **저장공간**: 체크포인트 1개 약 8MB(가중치 + 옵티마이저 상태), 최종 모델 약 3MB.
- **배터리·발열**: CPU를 계속 쓰므로 20분 이상이면 발열로 속도가 떨어질 수 있다. 정량 수치는 측정 단계(8장 0단계)에서 수집한다.

## 6. 기능 요구사항

### 6.1 측정 (벤치마크)
- R-1: [학습] 탭에 "이 기기에서 측정" 버튼을 둔다. 10단계를 돌려 단계당 시간을 재고, 100·300단계 예상 시간을 보여 준다.
- R-2: 측정 결과에 따라 등급을 표시한다. 단계당 1초 이하 "적합", 1~5초 "느림", 5초 초과 "권장하지 않음".
- R-3: "권장하지 않음"이어도 학습을 막지 않고 경고만 한다.

### 6.2 학습 실행
- R-4: 학습은 Web Worker에서 실행해 화면이 멈추지 않게 한다.
- R-5: 진행률, 손실 값, 남은 시간, 일시정지·재개·중지 버튼을 보여 준다.
- R-6: 학습 중 화면 꺼짐을 막는다(Wake Lock). 지원하지 않는 브라우저에서는 "화면을 켜 두세요" 안내를 띄운다.
- R-7: 탭이 백그라운드로 가면 자동 일시정지하고, 돌아오면 이어서 진행한다.
- R-8: 단계당 시간이 처음의 2배를 넘으면(발열 추정) 자동으로 쉬었다가 재개하는 옵션을 둔다.
- R-9: 배터리 정보가 있는 브라우저에서는 "충전 중일 때만", "배터리 N% 이하면 중지" 조건을 지원한다. 정보가 없는 브라우저(iPhone Safari 등)에서는 시간 제한만 적용한다.

### 6.3 체크포인트와 재개
- R-10: N단계마다(기본 20) 가중치와 옵티마이저 상태를 기기 저장소(IndexedDB)에 저장한다.
- R-11: 브라우저가 종료되어도 다음 실행 때 "이어서 학습" 버튼으로 재개한다.
- R-12: 저장 공간이 부족하면 학습 시작 전에 알려 준다.

### 6.4 평가
- R-13: 학습 전후 평가 손실을 비교해 보여 준다. 나빠졌으면 "이전 모델 유지"를 기본 선택으로 한다.
- R-14: 학습 후 샘플 문장을 생성해 보여 준다.

### 6.5 PC와 동기화
- R-15: 휴대폰에서 학습한 모델을 PC로 올린다. PC는 이를 새 모델 버전으로 등록하고 부모 모델, 단계 수, 학습 기기를 기록한다.
- R-16: 올리기는 관리자 PIN으로 로그인한 경우에만 가능하다.
- R-17: PC는 올라온 가중치의 구조와 크기, 값(유한한 숫자인지)을 검증한 뒤 등록하고, ONNX(fp32, int8)를 다시 만든다.
- R-18: 같은 부모에서 PC와 휴대폰이 각각 학습한 경우 두 모델을 별도 버전으로 보관한다. 자동 병합은 하지 않는다.

### 6.6 정책
- R-19: 온디바이스 학습은 인터넷을 쓰지 않으므로 수집 허용 시간대의 제한을 받지 않는다. 단, 자료 사본 받기와 모델 올리기는 PC 접속이 필요하다.
- R-20: 학습 시작·종료, 올리기는 PC 동기화 시 감사 기록에 남긴다.

## 7. 기술 접근 (후보와 추천)

| 후보 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 자체 학습 엔진 (추천) | 순전파·역전파·AdamW를 직접 구현 (JS + WASM SIMD) | 외부 의존 없음, 모델 구조가 고정이라 구현 범위가 명확 | 구현·검증 작업량이 큼 |
| B. onnxruntime-web 학습 기능 | 학습용 ONNX 묶음을 PC에서 만들어 휴대폰에서 실행 | 직접 구현이 적음 | 웹 학습 기능의 지원 지속 여부가 불확실. 사전 조사 필요 |
| C. WebGPU 가속 | GPU로 행렬 연산 | 빠름 | 지원 기기가 제한적. 1차 범위에서 제외하고 후속 검토 |

- 추천: **A로 시작**하고, 0단계에서 B의 지원 상태를 조사한다.
- 정확성 기준: 같은 가중치와 입력에 대해 PC(PyTorch)와 손실 값 차이 1e-3 이하, 기울기 차이 1e-2 이하(상대 오차).
- 휴대폰 추론은 기존 ONNX 경로를 유지한다. 휴대폰에서 학습한 직후에는 학습 엔진의 순전파로 생성하고, PC 동기화 후 ONNX로 교체한다.

## 8. 단계별 진행

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0. 측정 | 순전파·역전파 최소 구현으로 실제 휴대폰 3종(저·중·고사양)에서 속도, 메모리, 발열 측정. 후보 B 조사 | 5장 추정치를 실측값으로 교체, 진행 여부 결정 |
| 1. 학습 엔진 | Worker 학습, 체크포인트, 재개, 평가 | PC 대비 정확성 기준 통과, 100단계 완주 |
| 2. 화면 | 측정 버튼, 진행 화면, 조건 설정 | 360px 화면에서 조작 가능, 오류 안내 한국어 |
| 3. 동기화 | 올리기 API, 검증, 버전 등록, ONNX 재생성 | 휴대폰 학습 모델이 PC 모델 목록에 표시되고 실행됨 |

**0단계 중단 기준**: 중급 휴대폰에서 단계당 5초를 넘거나 10분 내 발열로 속도가 절반 이하가 되면, 이 기능을 보류하고 "PC 학습 + 휴대폰 지시" 구조를 유지한다.

## 9. 성공 지표

- 중급 휴대폰에서 나노 100단계 학습이 10분 이내에 끝난다.
- 중단 후 재개 성공률 95% 이상 (브라우저 강제 종료 포함).
- 100단계 이어서 학습 후 평가 손실이 학습 전보다 낮다 (자료 사본 1,500조각 기준).
- 휴대폰 학습 모델의 PC 등록 성공률 99% 이상.

## 10. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 실제 속도가 추정보다 느림 | 기능 가치 하락 | 0단계 측정과 중단 기준 |
| 발열·배터리 소모 | 기기 부담, 사용자 불만 | 시간 제한, 자동 휴식, 충전 조건 |
| 브라우저가 탭을 종료 | 진행분 손실 | 20단계마다 체크포인트 |
| iPhone Safari의 제약 (메모리, 배터리 정보 없음) | 일부 조건 미지원 | 시간 제한만 적용, 지원 범위 명시 |
| 적은 자료로 과하게 학습 | 문장 베끼기 | 평가 손실 비교, 나빠지면 이전 모델 유지 |
| 올린 가중치의 손상·조작 | PC 모델 오염 | 구조·값 검증, 관리자만 올리기 |

## 11. 결정이 필요한 항목

1. 0단계 측정에 쓸 실제 휴대폰 기종 (최소 Android 1대, iPhone 1대)
2. 처음부터 학습을 1차 범위에 넣을지 (기본안: 이어서 학습만)
3. 사용자 PIN으로도 휴대폰 학습을 허용할지 (기본안: 학습은 누구나, PC 올리기는 관리자만)
4. 발열 자동 휴식을 기본으로 켤지
